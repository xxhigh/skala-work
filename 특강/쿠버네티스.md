## 서버 및 서비스 개념

서비스 초기 -> 서버 한 대면 충분!
서비스가 커지면?
1. 서버의 성능을 높이자! -> Scale Up 방식
	- 단순하지만, 무한정 성능을 올릴 수 없음
	- 서버 한 대가 죽으면, 서비스 전체가 죽음
2. 서버를 여러 대 사용하자! -> Scale Out(서버의 수를 늘림) / Scale In(줄임)
	- 서버 A에 접근해서 사용 중, 서버 B에 접근했을 때 기존 인증으 어떻게 해야하나?
	- 공유하는 정보는 서버끼리 공유하자.

Stateless (일반적인 서비스)
- 사용자의 상태를 서버에는 저장하지 않고 외부에 둠.
Stateful (일부분의 기능)
- 사용자의 상태를 서버에 저장.

서버가 여러 대면 요청은 어디로? -> 로드 밸런싱

## 쿠버네티스 개념

컨테이너를 여러 개 띄워도 끝이 아니다!
- 어떤 기준으로 보내고
- 죽으면 어떻게 살리고
- 어떻게 늘릴 것인지
그렇기 떄문에 사람이 하기 힘들다. -> 쿠버네티스가 등장한 이유.

대표적인 핵심 기능: 배치, 개수 유지, 복구, 확장, 연결 관리

수평 확장, 로드 밸런싱, 롤아웃/롤백, 자동화된 복구(죽은 컨테이너는 버리고, 해당 이미지와 똑같은 이미지로 새롭게 구성), 빈 패킹Bin Packing

## 쿠버네티스 구성요소

클러스터 - 쿠버네티스가 관리하는 전체  환경
노드 - pod가 실행되는 서버
pod - 컨테이너를 실행하는 기본 단위 (파드 하나에 여러 컨테이너를 띄울 수도 있음. 메인+서브)
컨테이너 - 서비스

기본원칙 - 원하는 상태를 '선언'한다. 매니페스팅
리소스 = 쿠버네티스가 관라하는 대상

디플로이먼트 - 컨테이너를 여러 개를 띄우고 유지하고 싶다.
- deployment.yaml을 작성해, 원하는 상태를 작성

서비스 - 파드가 계속 바뀔 수 있는데, 어떻게 접근할 지.
- 사용자는 서비스에 대한 주소만 알고 있으면, 서비스가 어떤 파드에 접근할 지 알려줌.
- service.yaml을 작성
