## 기초 개념 (리마인드)

### IP & Port

**IP 주소**
- 인터넷에서 특정 컴퓨터를 식별하기 위한 논리적 주소
**Port**
- IP 주소를 가진 Host 내에 실행중인 서비스/프로세스를 구분하는 번호
- 외부에게 애플리케이션을 보여주기 위해 포트 번호를 사용
- 내부에서 통신시 필요 없는 경우가 더 많음

### Localhost & 127.0.0.1

- 동일 Host 내에서 프로세스 간 통신을 위한 Domain Name(localhost), IP(127.0.0.1)
- 127.0.0.1 = LoopBack IP

### Process & Port

프로세스
- 현재 메모리에 로드되어 CPU를 할당받고 실행 중인 프로그램

외부 프로세스간 통신
- IP + Port
- 172.8.32.9:8080

내부 프로세스간 통신
- 127.0.0.1 + Port
- 127.0.0.1:8080, localhost:8080

### Process & Thread

| 항목     | 프로세스                       | 스레드                     |
| ------ | -------------------------- | ----------------------- |
| 정의     | 실행 중인 프로그램의 인스턴스           | 프로세스 내에서 실행되는 작업 단위     |
| 메모리 공간 | 독립적인 메모리 공간 사용             | 프로세스의 메모리 공간을 공유        |
| 생성 비용  | 상대적으로 크고 무겁다               | 생성 비용이 낮고 가볍다           |
| 통신 방법  | IPC (파이프, 소켓 등) 필요         | 공유 메모리를 통해 간단하게 통신 가능   |
| 충돌 영향  | 다른 프로세스에 영향 없음             | 다른 스레드에 영향을 줄 수 있음      |
| 예시     | 웹 브라우저, 게임, IDE 등 독립 실행 환경 | 웹 페이지 렌더링, 백그라운드 다운로드 등 |
- 프로세스는 힙 메모리에 할당받고 자신의 차례가 되면 CPU에 올라가서 작업을 한다. (스케쥴링)
- 메모리를 초과하면 프로세스는 강제 종료 (Out of Memory)
- 스레드는 프로세스 안에서 실행하는 작업 단위

### Public IP & Private IP

- 특정 private network 내에서만 유일한 식별자 private IP (대부분 private IP)
- 32비트 IP 구성으로는 현재 세상의 모든 전자기기에 할당할 수 없음
- 그래서 서로 내부에서는 따로 식별할 수 있는 private IP를 사용하고 외부 통신을 이용할 때만 Public IP를 사용
- 나갈 때 포트번호를 통해 어떤 내부 IP를 사용했는지 식별할 수 있도록 함.

### Application Layer 진입점: 소켓(Socket)

- OS 커널이 제공하는 프로세스가 네트워크를 통해 통신하기 위해 추상화된 통신 엔드포인트
- 소켓은 특정 포트 번호와 연결되어 있어서 TCP에서 데이터를 보낼 응용 프로그램을 식별

### 응용 계층 프로토콜: HTTP(s)

- 웹에서 데이터를 주고받기 위한 통신 규약
- 응용 계층(애플리케이션 내부) 클라이언트가 서버에 요청을 보내면 서버는 해당 요청에 대한 응답을 돌려주는 방식

### HTTP Method

- GET
- POST
- PUT
- DELETE

### Gateway, Router, Load Balancer

**Router**
- 네트워크 연결/확장, 길을 만드는 기능
- 인터넷 자체가 라우터들의 집합
- Layer 3

**Gateway**
- 서비스/애플리케이션으로 진입하기 위한 진입점
- 프로토콜의 변환
- 외부 IP를 내부 IP로 변환
- 각종 인증, 필터, 헤더 변경
- Layer 7 Routing + Service LoadBalancer (Optional)

**Load Balancer**
- 요청  트래픽을 여러 노드에 분배 및 분산
- Layer 4
- Layer 7

### REST 설계원칙

| #   | 설계 원칙            | 필수/선택 |
| --- | ---------------- | ----- |
| 1   | 클라이언트-서버 분리      | 필수    |
| 2   | 무상태성(Stateless)  | 필수    |
| 3   | 캐시 가능(Cacheable) | 필수    |
| 4   | 일관된 인터페이스        | 필수    |
| 5   | 계층 구조            | 필수    |
| 6   | 코드 온 디맨드         | 선택    |

- **무상태성**
	- 서버는 클라이언트의 세션 상태를 보관하지 않음
	- 요청 간 상태를 기억하지 않으므로, 각 요청은 완전한 독립성 보장
	- 요청에는 인증/권한/요청 처리에 필요한 정보를 항상 포함(Header, JWT, Cookie)
- **캐시가능**
	- 응답은 명확히 캐시 가능 여부를 나타냄
	- 캐싱을 통해 네트워크 비용을 줄이고 응답 속도를 개선
	- HTTP 캐시 기능(Cache-Control, ETag 등)을 활용하는 것이 REST의 원칙

### OSI 7 Layer

| Layer | 정의                                                        | 대표 정보/기능               |
| :---: | --------------------------------------------------------- | ---------------------- |
|  L7   | 사용자가 사용하는 애플리케이션의 네트워크 서비스와 메시지의 의미를 정의하는 계층              | HTTP, SMTP, DNS 등      |
|  L6   | 애플리케이션 데이터를 상대방이 이해할 수 있도록 표현 형식을 변환하는 계층                 | 인코딩, (역)직렬화, 압축, 암호화   |
|  L5   | 두 애플리케이션 간의 논리적인 대화/연결 상태를 설정, 유지, 종료하는 계층                | 세션 관리, 대화 상태           |
|  L4   | 데이터를 어떤 프로세스(Port)로 전달할지 결정하고 종단 간 전송을 관리하는 계층            | TCP/UDP, Port, 재전송, 순서 |
|  L3   | 데이터를 어떤 컴퓨터(IP)까지 어떤 경로로 전달할지 결정하는 계층                     | IP, Routing            |
|  L2   | Bit에서 Frame의 경계를 식별하고 MAC 주소 등을 해석하여 같은 네트워크 구간에서 전달하는 계층 | Ethernet, MAC, Frame   |
|  L1   | Bit를 전기, 빛, 전파 등의 물리 신호로 변환하거나 그 반대로 변환하는 계층              | Bit, 전기, 광, RF         |

L5 L7: 세션 유지, 콘텐츠 기반 분산
L4: TCP/UDP 포트 기반 트래픽 처리
L3: 서로 다른 네트워크 간 통신
L2: 같은 네트워크 내 MAC 기반 통신
L1: 신호전송


## 리눅스 이해하기

1991년 리누스 토발즈가 Unix-like 시스템인 Linux를 무료로 공개
- 사용자 프로그램이 하드웨어를 직접 다루지 않고도 사용할 수 있도록 지원하는 하드웨어 추상화 + 자원관리 계층
- Unix 철학 유지
- 오픈소스

리눅스는 커널이며, 다양한 조합을 통해 배포판으로 구성됨.
- Linux Kernel
- GNU Utility
- Package Manager
- Desktop Env
- Driver/Tool

OS Category
- Ubuntu
- Debian
- Red Hat Enterprise Linux (RHEL)
- CentOS
- Alpine

### 리눅스 쉘

**Shell**
- 사용자와 커널 사이의 인터페이스
- 사용자 명령을 해석해서 커널에 전달하는 프로그램
- 대표적으로 zsh, bash, sh

### 쉘 초기화 스크립트

사용자가 쉘을 실행할 때 자동으로 읽혀서 환경변수, alias, prompt, 함수, PATH 설정을 적용하는 설정 파일

~/.bashrc - bash
~/.zshrc - zsh
~/.profile - sh(POSIX 표준)

### 리눅스 파일 시스템

| 디렉토리  | 설명                                                                                                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| /     | 파일시스템의 최상위                                                                                                                                                                    |
| /bin  | OS 필수 명령 실행 파일(프로그램). 예: bash, ls, mount, tar                                                                                                                                 |
| /boot | 부팅에 필요한 커널 이미지. 초기 램 디스크 이미지등이 저장된 디렉토리                                                                                                                                       |
| /dev  | 하드웨어, 가상장치를 파일 인터페이로 노출한 디렉토리. 장치 파일은 읽고 쓰는 순간 커널 드라이버 코드가 실행되는 툭수 파일. <br>`/dev/null: 쓰면 버려지는 장치`<br>`/dev/tty: 현재 프로세스의 터미널`<br>`/dev/sda: SCSI/SATA 디스크`                   |
| /etc  | 시스템 설정 파일이 저장된 디렉토리. /etc/hosts, /etc/passwd                                                                                                                                  |
| /home | 사용자 개인 홈 디렉토리 저장 위치.                                                                                                                                                          |
| /lib  | 시스템 라이브러리 저장. 기본 시스템 명령어와 함께 동작하는 공유 라이브러리가 포함                                                                                                                                |
| /root | 루트 사용자의 홈 디렉토리                                                                                                                                                                |
| /sbin | 시스템 관리용 필수 바이너리 (fdisk, fsck, init)                                                                                                                                           |
| /tmp  | 임시 파일 저장 위치. 모든 사용자가 임시 파일 생성 가능                                                                                                                                              |
| /usr  | 사용자 관련 프로그램과 데이터가 저장되는 디렉토리, 하위 디렉토리에는 바이너리, 라이브러리, 문서 포함.<br>`/usr/bin: 시스템 표준 명령어. apt install로 설치되는 대부분의 실행 파일`<br>`/usr/local/bin: 사용자가 직접 설치하는 명령어. kubectl, helm, kind` |
| /var  | 로그 파일, 캐시 파일, 재부팅한 후에도 유지되는 임시 파일 등이 저장                                                                                                                                       |

## 컨테이너의 이해

### 가상화

- 물리적인 하드웨어를 추상화하여 소프트웨어로 구현하는 기술
- 한 컴퓨터를 독립된 여러 대의 컴퓨터처럼 사용할 수 있도록 지원

### Hypervisor

- 물리 서버 위에서 여러 개의 가상 머신을 생성, 실행, 관리하는 소프트웨어 계층

### Hypervisor 유형

**Type1**
- 경량 전용 OS, 전용 하드웨어, 원격 관리 도구 지원
- 클라우드 IDC, 데이터 센터용

**Type2**
- 기존 장비에 가상화 환경 구성시 활용
- 데스크탑 테스트/개발용
