- Question : 본인이 그리는 5년 뒤 모습에서 본 SKALA 교육과정이 갖는 의미는 무엇인가요? (800자 이내)
- Answer :
    5년 후 저는 AI의 기술적 한계와 가능성을 명확히 구분하여, 비즈니스 현장에 최적화된 AI 솔루션을 구현하는 ‘실무형 DT 전문가’가 되어 있을 것입니다. 현재 AI 기술은 급격한 발전을 거쳐 산업 안정기에 진입했지만, 대다수는 AI가 생성한 결과물에 의존하는 수동적 활용에 머물러 있습니다. 저 또한 정교한 컨텍스트로 질문을 던지는 수준을 넘어, AI 모델의 메커니즘을 본질적으로 이해하고 이를 비즈니스 난제 해결에 이식하는 능력이 필요함을 절감했습니다.  
      
    이러한 관점에서 SKALA 교육과정은 저에게 막연한 가능성을 확신 있는 기술력으로 전환하는 결정적인 도약대라 생각합니다.  
      
    첫째, ‘AI 리터러시’의 고도화입니다. 현직 전문가들과의 밀착 멘토링을 통해 AI가 할 수 있는 것과 없는 것을 날카롭게 선별하는 안목을 기르겠습니다. 이는 자원을 낭비하지 않고 최적의 효율로 DT 프로젝트를 리딩할 수 있는 판단력의 밑거름이 될 것입니다.  
      
    둘째, 현장 중심의 실전 역량 확보입니다. SKALA의 커리큘럼은 단순히 이론을 학습하는 과정이 아니라, 현업의 데이터를 다루며 기술의 실효성을 검증하는 과정이라 확신합니다. 타협 없이 끝까지 파고드는 집요함을 바탕으로, 산업 인프라 위에서 실제 작동하는 AI 모델을 구축해 본 경험은 훗날 제가 디지털 혁신을 주도하는 리더로 성장하는 데 대체 불가능한 자산이 될 것입니다.  
      
    단순히 AI를 잘 사용하는 개발자에 그치지 않고, 기술의 본질을 이해하고 완성하는 핵심 인재로 거듭나겠습니다.

- **기술 경험**
- Question : 프로그래밍이나 AI/Data 경험 중 본인을 가장 성장시켰던 경험과 본인의 역할, 어려움을 극복한 방법, 느낀점 등에 대해 기재해주세요. (1,000자 이내)
- Answer :
    Unreal Engine 5 환경에서 상용화를 목표로 ‘실시간 스켈레탈 메쉬 절단 플러그인’을 개발하며, 기술적 한계를 데이터 기반의 최적화로 극복한 경험이 저를 가장 크게 성장시켰습니다.  
      
    개발 중 직면한 가장 큰 어려움은 성능 병목 현상이었습니다. 절단면의 버텍스 데이터를 실시간으로 재구축하고 물리 연산을 적용하는 과정에서 급격한 프레임 드랍이 발생했습니다.
    
    특히 복잡한 애니메이션이 적용된 캐릭터 모델의 경우, 연산 시간이 16ms를 초과하여 게임의 실시간성을 해치는 치명적인 결함이 확인되었습니다. 저는 단순히 기능을 구현하는 수준에 만족하지 않고, 엔진의 코어 수준에서 문제를 해결하기 위해 집요하게 파고들었습니다. 
    
    첫째, 언리얼 엔진의 렌더링 파이프라인과 물리 엔진 소스 코드를 분석하여 병목 지점을 특정했습니다. 단일 스레드에서 처리되던 정점 연산 구조가 문제의 핵심임을 파악했습니다. 
    
    둘째, 데이터 처리 효율을 극대화하기 위해 병렬 연산구조를 설계했습니다. 절단면 폴리곤 생성 알고리즘을 최적화하고, 무거운 물리 계산을 비동기 태스크로 분리하여 메인 스레드의 부하를 분산시켰습니다. 
    
    셋째, 반복적인 프로파일링을 통해 메모리 누수를 추적하고, 데이터 캐싱 전략을 수정하며 0.1ms 단위의 연산 시간까지 단축하기 위해 매달렸습니다.  
      
    이러한 노력을 통해 런타임 성능을 기존 대비 35% 이상 개선하며, 끊김 없는 실시간 절단을 구현해냈습니다. 해당 플러그인은 Fab 마켓플레이스 출시 후, 기술적 안정성을 인정받아 평점 5.0을 기록하며 전 세계 개발자들에게 가치를 증명했습니다. 
    
    이 과정을 통해 기술적 난관 앞에서 직감에 의존하기보다, 철저한 데이터 분석과 근본적인 구조 개선으로 답을 찾아내는 개발자적 집요함을 얻었습니다.

## 자기소개서 실전 가이드

"자소서 작성에 정답은 없다."
마인드 셋: 컨설팅 내용, 우수 사례를 내 자소서에 조금씩 반영하려고 노력

### 1. 자소서는 어떻게 평가 하는가?

- 사람이 결정, 명백한 상위/하위권은 AI의 적용이 가능하지만, 작은 편차나 중위권은 면밀한 판단이 어려움.
- 인사 담당자 자소서 평균 검토 시간 - 5분 미만(62%)
	- 읽지 않고 스캔하는 방식
	- 남이 쓴 것을 베껴도 느낌으로 알 수 있음
	- 열심히 혹은 잘, 회사는 배우는 곳이 아님.

### 2. 인사담당자는 무엇을 보고 결정하는가?

- 스펙보다 자소서가 결정한다.
	- 자소서가 완벽하면 합격시키겠다.(61%)
	- 스펙이 완벽해도 자소서가 부실하면 탈락시키겠다(73%)
- 스펙은 입장권이라면, 합격을 가르는 건 결국 자소서.
- 문항 중 가장 중요하게 평가하는 요소
	1. 직무 경험(34%)
	2. 지원 동기(23%)
	3. 가치관 성격(18%)
	4. 입사 후 포부(10%)
- 감점요인
	- 너무 짧거나 급하게 써서 무성의해 보이는 자소서
	- 다른 회사 이름이나 지원 부서를 잘못 적은 자소서
	- 근거 없는 역량의 과잉 기술
	- 빈약하고 불분명한 성과
### 3. 자기소개서는 어떻게 활용되는가?

- 서류 전형, 면접 전형 모두 활용됨
- 자소서의 문장이 면접 질문의 소스
	- 애매하게 쓴 문자 = 곤란한 질문
- 두괄식으로 정리된 자소서는 훌륭한 답변 시나리오
- 면잡관의 질문을 내가 유리한 방향으로 유도할 수 있는 트리거

### 4. 자소서 잘 쓰는 방법은?

- STAR, 두괄식으로 작성하기
- _두괄식은 만약 3단락이 있다면 첫 단락에 핵심 주제가 나와야함._

기본기 3가지
1. 기업명 오기재 확인
2. 글자 수 & 오타검사
3. 블라인드 규정 준수

심화 3가지
1. 두괄식 구조
2.  STAR 기법
3. 숫자 중심 성과 - 비교 가능한 수치 추가 필수

주요 문항 작성 가이드
- 지원 기업의 최근 사업 분야, 성과 분석 결과 (구체적으로) 등과 개인 경험, 목표와 교집합 도출
- 단점은 사실로 쓰지말고, 장점인듯 아닌듯한 느낌의 단점을 작성
- 입사 후 포부는 단계적 설계 및 현실적이고 구체적인 목표로 작성, 예) 5년 후: 3년 -> 5년

소제목은 흥미를 유발시킬 수 있다면 작성하는 것이 좋음. 그게 아니라면 그냥 두괄식만 작성.

## **기술 경험**
- Question : 프로그래밍이나 AI/Data 경험 중 본인을 가장 성장시켰던 경험과 본인의 역할, 어려움을 극복한 방법, 느낀점 등에 대해 기재해주세요. (1,000자 이내)
- Answer :

    게임 엔진 플러그인 '실시간 스켈레탈 메쉬 절단 플러그인'을 개발하며, 기술적 한계를 데이터 기반의 최적화로 극복하고 성능 40% 개선 및 Fab 마켓플레이스 평점 5.0을 달성한 경험이 저를 가장 크게 성장시켰습니다.

    당시 복잡한 애니메이션이 적용된 캐릭터 모델을 절단할 때, 절단면 버텍스 재구축과 물리 연산으로 인해 연산 시간이 16ms를 초과(60fps 미달)하며 치명적인 프레임 드랍이 발생하는 문제에 직면했습니다. 
    저는 메인 개발자로서 엔진 코어 수준에서 병목을 확인하고 런타임 실시간성을 확보하는 것을 최우선 과제로 설정했습니다. 이 문제를 해결하기 위해 예측에 의존하지 않고 철저한 분석과 구조 개선에 집중했습니다

    첫째, 언리얼 엔진의 렌더링 파이프라인과 물리 엔진 소스 코드를 분석하여 병목 지점을 특정했습니다. 단일 스레드에서 처리되던 정점 연산 구조가 문제의 핵심임을 파악했습니다. 
    둘째, 데이터 처리 효율을 극대화하기 위해 병렬 연산구조를 설계했습니다. 절단면 폴리곤 생성 알고리즘을 최적화하고, 무거운 물리 계산을 비동기 태스크로 분리하여 메인 스레드의 부하를 분산시켰습니다. 
    셋째, 반복적인 프로파일링을 통해 메모리 누수를 추적하고, 데이터 캐싱 전략을 수정하며 0.1ms 단위의 연산 시간까지 단축하기 위해 매달렸습니다. 

    이러한 노력을 통해 기존 런타임 성능 대비 40% 이상 개선하며, 끊김 없는 실시간 절단을 구현해냈습니다. 해당 플러그인은 Fab 마켓플레이스 출시 후, 기술적 능력을 인정받아 평점 5.0을 기록하며 다른 개발자들에게 가치를 증명했습니다. 

    이 과정을 통해 기술적 난관 앞에서 직감에 의존하기보다, 데이터 분석과 근본적인 구조 개선으로 답을 찾아내는 개발자적 집요함을 얻을 수 있었습니다.
