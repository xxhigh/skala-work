# SKALA 스터디 플래너

학습 목표를 등록하고, 진행 상태와 마감일을 관리하는 정적 웹 애플리케이션입니다. 별도의 백엔드 없이 브라우저의 `localStorage`에 데이터를 저장하며, 오늘의 팁은 JSON 파일에서 불러옵니다.

## 1. 구현 기능 목록

- ✅ 목표추가 (F1)
- ✅ 완료 토글 및 삭제 (F2)
- ✅ 필터 및 진행률 (F3)
- ✅ localStorage 저장 (F4)
- ✅ 마감일 입력 (F5)
- ✅ 검색 (F6)
- ✅ 분류별 요약 (F7)
- ✅ 반응형 디자인
- ✅ 다크모드
- ✅ 애니메이션

| 기능 | 설명 |
| --- | --- |
| 학습 목표 추가 | 목표명, 카테고리(HTML/CSS/JavaScript), 마감일을 입력해 항목을 등록합니다. 필수값이 비어 있으면 오류 메시지를 표시합니다. |
| 완료 상태 변경 및 삭제 | 체크박스로 완료 여부를 변경하고, 삭제 버튼으로 목표를 제거할 수 있습니다. |
| 필터 및 검색 | 전체·진행 중·완료 상태별로 목록을 필터링하고, 목표명으로 검색합니다. |
| 진행률 및 카테고리 요약 | 전체 대비 완료 비율과 카테고리별 미완료 목표 수를 표시합니다. |
| 마감일 표시 | 마감일을 기준으로 `D-Day`, `D-n`, `D+n` 형식의 남은 일수를 보여 줍니다. |
| 로컬 저장 | 목표 목록과 선택한 테마를 `localStorage`에 저장해 새로고침 후에도 유지합니다. |
| 다크 모드 | 시스템 설정을 초기값으로 적용하며, 테마 토글 버튼으로 변경한 선택값을 저장합니다. |
| 항목 애니메이션 | 새 목표는 진입 애니메이션을 적용하고, 삭제한 목표는 원래 화면 위치에서 사라지도록 처리합니다. |
| 반응형 UI | 화면 폭이 좁으면 폼과 패널 레이아웃이 한 열로 전환됩니다. |

## 2. 실행 방법

이 프로젝트는 `js/app.js`에서 `fetch("data/tips.json")`를 사용합니다. 따라서 `index.html` 파일을 브라우저에서 직접 열지 말고, HTTP 서버를 통해 실행해야 합니다.

### 1. Live Server로 실행

1. VS Code에서 프로젝트 폴더를 엽니다.
2. **Live Server** 확장을 설치합니다.
3. `index.html`을 열고, 상태 표시줄의 **Go Live**를 선택합니다.
4. 브라우저에 표시된 로컬 주소(예: `http://127.0.0.1:5500`)로 접속합니다.

### 2. Docker로 실행

프로젝트 루트에서 다음 명령을 실행합니다.

먼저 현재 폴더 구조의 정적 파일을 모두 포함하는 `Dockerfile`을 생성합니다.

```powershell
@'
FROM nginx:alpine

COPY index.html /usr/share/nginx/html/
COPY css /usr/share/nginx/html/css
COPY js /usr/share/nginx/html/js
COPY data /usr/share/nginx/html/data

EXPOSE 80
'@ | Set-Content -Encoding utf8 Dockerfile
```

이미지를 빌드합니다.

```powershell
docker build -t skala-planner .
```

컨테이너를 실행합니다.

```powershell
docker run --rm -p 8080:80 skala-planner
```

실행 후 브라우저에서 [http://localhost:8080](http://localhost:8080)에 접속합니다. 종료하려면 실행 중인 터미널에서 `Ctrl + C`를 누릅니다.

## 3. 어려웠던 점과 해결

### 검색 기능: 원본 데이터와 표시 목록의 분리

검색 결과만 보여 주기 위해 `goals` 자체를 검색 결과로 교체하면, 검색어를 지웠을 때 이전 항목을 복원할 수 없고 이후 추가·삭제·필터 동작도 불안정해집니다.

이를 해결하기 위해 `goals`는 전체 원본 데이터로 유지하고, 검색 시에는 `filter()`로 만든 결과 배열만 `render()`에 전달했습니다. 검색어가 비어 있으면 현재 필터 조건에 맞는 `visible()` 결과를 다시 렌더링합니다. 이 방식은 검색이 데이터 변경이 아닌 **표시 상태 변경**으로 동작하고 있습니다.

### 애니메이션: 전체 재렌더링 방지

기존 구현처럼 목록 컨테이너의 `innerHTML`을 비운 뒤 모든 항목을 다시 생성하면, 목표 하나를 추가하거나 삭제해도 전체 항목이 새 DOM 요소가 됩니다. 그 결과 특정 항목에만 애니메이션을 적용하기 어렵고, 모든 목록이 동시에 움직이는 문제가 발생했습니다.

각 항목의 `id`를 `data-id`로 사용해 기존 DOM 요소를 재사용하도록 변경했습니다. 새로 생성된 항목에만 진입 클래스를 부여하므로 추가 애니메이션이 필요한 항목을 정확히 구분할 수 있습니다.

### 삭제 애니메이션: 원래 위치에서 자연스럽게 제거

삭제 대상 요소를 목록에 남긴 상태로 나머지 요소를 다시 정렬하면, 삭제 대상이 목록의 맨 위나 다른 위치로 이동한 뒤 사라지는 문제가 있었습니다.

삭제 직전 요소의 화면 좌표를 읽어 동일한 복제 요소를 `position: fixed`로 배치하고, 원본 요소는 목록에서 즉시 제거했습니다. 복제 요소만 퇴장 애니메이션을 수행한 뒤 제거하므로, 목록은 즉시 재배치되면서도 삭제 항목은 원래 자리에서 자연스럽게 사라집니다.

### 다크 모드: 하드코딩 색상 관리

밝은 테마 색상을 여러 선택자에 직접 작성하면 다크 모드 추가 시 수정 지점이 늘어나고, 일부 컴포넌트만 밝은 색으로 남을 수 있습니다.

배경, 표면, 테두리, 텍스트, 그림자 색상을 CSS 사용자 정의 속성으로 통일하고 `body.dark`에서 변수값만 재정의했습니다. 테마 선택값은 `localStorage`에 저장하고, 저장값이 없을 때만 운영체제의 `prefers-color-scheme` 설정을 초기값으로 사용합니다.
