## AI 시대, 소프트웨어의 진화

### 소프트웨어 수명 주기의 구조적 변화

- **요구사항 정의**
	- 자연어로 작성된 요구사항 명세서가 곧바로 실행 가능한 프로토타입이나 코드로 변환
	- 기획 단계와 개발 단계 사이의 간극이 극적으로 줄어듬
- **구현**
	- 한 줄 한 줄을 타이핑하는 대신, 자율형 코딩 에이전트에게 기능 단위의 티켓을 위임
	- 에이전트는 레포지토리를 탐색하고, 의존성을 분석하며, 풀 리퀘스트를 자체 생성
- **테스트 및 디버깅**
	- AI가 엣지케이스를 예측해 유닛,통합 테스트 코드를 자동 생성
	- 런타임 로그 및 스택 트레이스를  분석하여 자가 치유 패치를 제안
- **유지보수 및 레거시 현대화**
	- 수백만 줄의 노후화된 레거시 코드 분석 및 현대적 아키텍처로 마이그레이션 소요 시간이 획기적으로 단축

### 코드 작성자에서 시스템 오케스트레이터로

1. **코드 작성에서 코드 검증으로**
	- 문법을 외우고 알고리즘을 손수 구현하는 역량은 AI로 대체
	- AI가 생성한 결과물의 정합성, 성능, 보안 취약점을 평가하는 코드 리뷰 및 검증 역량이 핵심
2. **아키텍처 및 시스템 설계 집중**
	- 마이크로서비스 간의 경계 설정, 데이터 흐름 제어, 분산 시스템의 신뢰성 확보 등 고차원적 의사결정에 더 많은 시간을 투입
3. **컨텍스트 엔지니어링**
	- AI에게 프로젝트 도메인 지식, 비즈니스 제약, 코딩 컨벤션을 효율적으로 주입하는 능력이 개발 생산성을 좌우

### 도전 과제

- **섀도우 코드와 기술 부채**
	- AI가 대량으로 생성한 코드를 사람이 완전히 이해하지 못하고 승인할 경우, 장기적인 유지보수성이 급격히 저하되는 '인지적 기술부채' 문제가 대두
- **공급망 보안 및 환각**
	- 존재하지 않는 라이브러리를 참조하게 만드는 환각 공격(Package Hallucination)이나 미묘한 보안 취약점 주입에 대응하기 위한 형식 검증 (Formal Verification) 도구의 필요성이 커짐
- **소프트웨어의 1회성/맞춤화**
	- 거대한 공용 소프트웨어를 구매하는 대신, 특정 팀이나 개인의 일시적 필요에 맞춰 몇 분 만에 생성되고 사용 후 폐기되는 초개인화 마이크로 앱의 비중이 증가

## 자연어 처리의 진화: LLM의 탄생

LLM의 성능을 결정짓는 3대 핵심 규모 요소
1. 사전 학습 코퍼스 규모
2. 학습된 파라미터 수
3. 연산 규모

### Bag of Words

- 처리 과정: 문장 분리 -> 단어 추출 -> 어휘 사전 구축 -> 빈도 벡터 생성
- 어휘 사전 크기만큼 벡터 차원이 커지므로 희소(Sparse) 벡터 문제 발생

### Word2Vec

- 기존의 희소 문제 해결, 의미적 유사도 반영(내적 및 코사인 유사도를 통해 단어 간의 유의 관계를 수치적으로 계산)
- 벡터 연산: 단어 간의 관계를 벡터 덧셈/뺄셈으로 추론 가능
	- (예: Vector(왕) - Vector(남자) + Vector(여자)≈ Vector(여왕))
